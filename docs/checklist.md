# FinClarity — Build Checklist

## Build Preferences

- **Build mode:** Step-by-step
- **Comprehension checks:** Yes — after each item, a short question to confirm the piece makes sense before moving on
- **Git:** Commit after each item with message: `Complete step N: [title]`
- **Verification:** Yes — run the app after each item and confirm what you see before moving to the next
- **Check-in cadence:** Balanced — PM-relevant explanations of what was just built and how it connects, without going deep into code detail

- [x] **12. Anonymous upload: process in memory, never save to DB**
  Spec ref: New — not in original spec (Option B data privacy decision)
  What to build: Change `app/api/statements/upload/route.ts` to detect whether the logged-in user is anonymous (Supabase sets `user.is_anonymous = true`). Update `app/dashboard/page.tsx` to check `sessionStorage` for pending data when the user is anonymous — if found, render the dashboard from that in-memory data instead of fetching from the API.   Acceptance: An anonymous user uploads a statement, sees their dashboard populated with real data, but the Supabase `transactions` and `monthly_reports` tables have zero new rows. Closing the tab and reopening shows an empty state (data gone). An authenticated user uploading still saves to DB as before — no regression.
  Verify: Upload a statement without signing in. Open Supabase → Table Editor → transactions. Confirm no new rows were inserted. Check browser DevTools → Application → sessionStorage — confirm `finclarity_pending_upload` key exists with transaction data. Close the tab, reopen the app — confirm the dashboard is empty.
